# 焊缝识别 Next.js 前端

按《NextJS 前端需求开发说明书 V1.0》整理前端功能与接口；实际后端字段仍需在接入前核对。保留用户允许的七个入口；取消固定画布缩放，工作区铺满窗口。代码不改动既有 FastAPI、模型、相机驱动或 FTP 服务。

## 启动

Node.js 24 LTS。仓库根目录：

```cmd
git pull origin main
npm run dev
```

自动检查前端依赖；后续普通源码更新跳过安装。浏览器访问终端的 Local 地址，默认 http://localhost:3000。生产使用根目录 `npm run build`、`npm start`，默认监听 0.0.0.0:3000。首次安装慢可设置 npm 镜像，构建后的网页不加载 CDN 或远程字体。

复制 `.env.example` 为 `frontend/.env.local`：

```dotenv
BACKEND_ORIGIN=http://127.0.0.1:8000
NEXT_PUBLIC_DATA_MODE=live
```

修改环境变量后重启开发服务；生产重新构建。未设置模式时默认离线示例；复制示例环境文件后使用 live 模式，真实请求走同源 `/api`，后端连接失败不会自动模拟成功。

## 离线开发与自测

说明书的离线开发：在既有后端设置 `WEBAPP_NO_MODEL=1`，保持前端后端模式，选择后端真实帧 `sw2_e30`，勾选「复用历史结果」，读取已有 `out/weld2tp/sw2_e30` 产物。没有模型不阻止其他界面；没有相机则显示采集任务失败日志。

此外提供单独的「浏览器自测」夹具，供没有后端时查看交互。通过右上设置切换，或设置 `NEXT_PUBLIC_DATA_MODE=demo`。它不是 FastAPI 历史产物验收，不执行推理、不连接相机和控制器；其中 .LS 示例不能用于真机。

当前仓库不含说明书的 `webapp/`、模型与 `out/weld2tp/sw2_e30`。实际后端与历史数据需由原项目提供，不伪造已完成联调。

| 坐标标定   | 可增删的点对表单、JSON/4×4 输入；标定点展示、状态/残差/矩阵/结果；清除二次确认。                               |
| 焊缝管理   | 编号/shape/type/长度、搜索和最短长度筛选、上下键选择；查看/预演/生成/下发四项操作，联动三维高亮。              |

## 布局与渲染约定

- 保留用户确认的布局：桌面侧栏 248px / 260px，中部弹性；<1200px 上下文面板并入左侧页签，采集页和其他工作台均可访问。三维视口至少 600px，过窄窗口在工作区内横向滚动。
- 按用户确认的版本保留字体、颜色、明暗主题及模块外观。部分辅助文字为 12–13px、浅色模式的视口为浅色，这是对原需求视觉条款的明确例外，不在本次接口修正中调整。没有整页缩放。
- 所有三维页面共用原 `PointCloud.tsx`，保留原 RAF 调度、抗锯齿、DPR 和点材质；不新增 FPS 限制、不改变 TCP 时间轴与播放速度。
- 相机系统一 `(x,-y,z)`，毫米；语义四类按说明书 RGB，实例使用黄金率 HSL，实例 0 深灰。点大小 1–6、本地颜色切换零请求、按 center/extent 重置、10mm 网格。
- 工作台视口状态条显示帧名、显示点数 n / 原始点数 n_full、实例数、来源、单位；采集页保留原有信息卡，预览标题悬停提示和无障碍描述补齐显示点数、原始点数及实例数，避免改变确认过的模块设计。内存缓存避免重复下载，卸载释放 Three.js 资源。
- `/api/view` 按定长二进制协议直接建立 TypedArray 视图，不将坐标转 JSON。额外支持 Worker 解析用户上传的 ASCII/binary/LZF PCD 原始预览，最多显示 400000 点；这与后端 `/api/view` 解析流程分开。
- 未标定可在确认后生成检查文件，保留红色「禁止上机」提示；当前 UI 会阻止该检查文件下发，需标定后重新生成。系统没有电机启动接口，传输确认只对应程序文件。

## 检查与验收边界

根目录：`npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。

另开服务 `npm start -- -p 3012`，在 frontend 执行：

```sh
APP_URL=http://localhost:3012 npm run test:ui
```

Windows CMD 设置变量用 `set APP_URL=http://localhost:3012`，再 `npm run test:ui`。

浏览器脚本 `scripts/requirements-check.cjs` 使用受控 HTTP 契约夹具验证 FR1–10，涵盖全屏/1366/窄屏、PCD Worker、缓存、本地配色、参数、采集/识别互斥、202/轮询/页面隐藏暂停/409、标定/残差/清除、焊缝键盘、程序/预演/下载、FTP 确认/覆盖/密码、任务中心。截图以 `screenshots/requirements-` 开头。

这些检查不能代替目标机器和真实设备验收。首屏 ≤2 秒、20万点下载+解析 ≤500ms、交互 ≥30fps、长期内存、Chrome/Edge 近两年版本、真实 sw2_e30 全链路、相机及 FTP 仍必须在项目组环境实测。具体请求嵌套字段以原 `webapp/schemas.py` 为最终权威，尤其 `pairs` 当前适配为 `{cam:[x,y,z],base:[x,y,z]}[]`。

部署和现场检查见根目录 `DEPLOYMENT.md`。

目标机器性能检查（需要已连接真实后端并准备历史产物）：在 frontend 执行 `npm run test:performance`，可通过 APP_URL 指定部署地址、CHROMIUM_PATH 指定 Chrome/Edge。输出 reports/performance.json，检查冷浏览器首个三维画面、真实视图下载和解析时间、20万点及交互 RAF 节奏。RAF 节奏是帧率近似，不能代替 GPU 完成时间和长时内存检查。本云环境缺真实后端，未冒充执行此现场验收。

## 后端接入准备与尚待确认的契约

- 正式 Next.js 默认 live；仅显式 `NEXT_PUBLIC_DATA_MODE=demo` 使用浏览器夹具。单文件 HTML 固定 demo，不提供 Next.js 代理，不能用作真实后端验收。
- `src/lib/backend-contract.ts` 集中管理标定点对序列化，当前字段为 `cam` / `base`。需求书没有定义该嵌套字段；拿到 `webapp/schemas.py` 后确认，只在适配层调整，不自动尝试多套请求。
- live 模式初始标定点对为空，不预填演示坐标。POST 标定返回的残差在会话内按帧保存；若 GET 标定不返回历史残差，只标注“未返回残差”，不伪造精度结论。
- 真实上传先 PUT 原始文件；仅后端视图 404 时按需尝试本地 PCD 预览。预览不支持某个文件时保留上传成功及无结果引导，不将其当成上传失败；500 等错误不会被本地预览掩盖。
- 支持 FastAPI 的字符串 detail 和 422 字段错误数组，不输出 input/ctx 中的提交内容。无效 JSON、无效 job_id、调用方取消与超时分别处理。
- 程序生成预算 120 秒。FTP HTTP 等待预算为 max(120 秒, 6 × timeout_s + 30 秒)，不修改发给后端的 timeout_s；超时不自动重试，并提示先核对后端结果。
- 完整验收脚本使用受控 HTTP 契约夹具；视觉脚本显式切换浏览器示例并拦截初始 API，不触达设备。测试不能代替目标后端、真实数据、相机、FTP 或性能验收。


## 展示模式（默认）

离线示例完全不连接后端和设备。内置点云、标定、程序、任务及下发均为模拟；上传的点云会实际解析。上传仓库 deliverables/demo_workpiece.pcd 可加载配套的两条模拟接缝，选择焊缝后生成程序、预演及模拟下发；接缝仅用于解释流程，不是识别算法输出。其他 PCD 只预览，不会套用配套焊缝。示例程序无运动指令，不可上机。

## 交给后端联调

1. 配置 frontend/.env.local：BACKEND_ORIGIN=http://127.0.0.1:8000，NEXT_PUBLIC_DATA_MODE=live，然后重启；生产环境需重新构建。也可以在设置切换“真实后端”。
2. 真实模式直接消费后端数据，不补模拟矩阵或伪造识别/FTP成功。空帧、无结果和接口失败保持真实状态。
3. 先验证 /api/health、/api/frames，再用后端 sw2_e30 历史产物测试点云和焊缝；无模型时 WEBAPP_NO_MODEL=1 配合复用历史结果。
4. 用后端认可的 PCD 测试 PUT /api/frames/{fid}。HTTP 500 必须检查后端日志，前端不会以本地成功掩盖服务错误。合成示例不是带历史产物的后端夹具，也不保证满足推理输入条件。
5. 核对 schemas.py 中点对的 cam/base 字段、ProgramReq、程序返回的 waypoints_cam_mm、waypoints_base_mm 和 wpr_list，以及视图二进制协议。GET 标定接口不保证返回 matrix，缺失时显示说明。
6. 识别完成会清除当前帧的点云缓存和旧程序，并重新读取点云、焊缝和标定。标定变更后需重新生成程序。
7. FTP 先指向测试服务器验证路径、字节数、覆盖及失败回执，再由项目组值守进行控制器联调。真实模式下发是真实文件传输，不发送机器人启动命令。

前端单元测试不能替代现场联调；当前未取得后端源码、服务日志和完整历史产物，上传500等服务错误尚未验证解决。
